# MPI-INF-3DHP S1/Seq2 — Rear-view DWPose Validation

Subject: S1 (single, 12,430 frames @ 50 fps), Activity: Sports
(boxing, tennis, golf, soccer). Processed every 2nd frame (~6,215 frames per camera).

Pipeline: DWPose-L (CoreML, 384x288 input, Halpe-26 remap) with bounding boxes generated by projecting MPI-INF-3DHP 2D GT joint annotations to tight padded boxes (15% pad).

GT angles computed directly from the dataset's 3D mocap (`annot3`, camera-0 coords), so they are camera-invariant. Predicted angles come from the 2D Halpe-26 keypoints in each camera's own image space using Couro's production `keypoints_to_motion_data` math.

## Assessment

Rear (cam 7) tracks the same biomechanics as front (cam 0) on the Couro core metrics:

- Hip flexion (sagittal, primary metric): rear matches or beats front (R-side +0.09, L-side +0.02).
- Knee flexion: rear within 0.07 of front (0.81 vs 0.88 R, 0.81 vs 0.78 L).
- Lumbar extension: rear -0.06 vs front (0.81 vs 0.87) — still strong.
- Ankle dorsiflexion: weak from both views (front 0.43 R, rear 0.31 R). This metric is dominated by toe keypoint noise + 2D foreshortening on either view.
- Hip adduction (coronal plane): weak from both views (<0.30). Expected — 2D coronal measurement is a noisy approximation from any single non-frontal camera.

**Verdict**: rear-view models are viable for the three metrics that already drive Couro reports (hip flexion, knee flexion, lumbar/trunk lean). DWPose does not collapse on rear views, contrary to the 'never validated' status of the v14 deploy slots. We should ship rear/rear-oblique deploys for hip+knee+lumbar; the ankle/adduction metrics remain a 3D-angle problem regardless of camera angle.

## Known caveats / failure modes

- **Confidence filtering drops 6–15% of frames** per metric (Halpe foot keypoints occasionally drop below 0.3 in extreme rear-view poses).
- **Sign-flipped hip-flexion** in this run: our 2D path computes `angle(torso, thigh)` interior whereas GT uses `angle(-torso, thigh)`. The signed Pearson is negative for all hip-flexion rows; `|r|` is the apples-to-apples number. Production motion-data code already applies the `180 - interior` flip; this validation script does not.
- **Single subject (S1) tested.** MPI-INF-3DHP has 8 subjects; results may shift on athletic body types vs the lab subject.
- **Stride 2** sampling means effective rate is 25 fps; still well-sampled for joint-angle correlations.
- The studio cameras are **3 m away with subject at screen-center**; this is best-case framing. Couro field videos with smaller-on-screen subjects may degrade more from rear views than from front views.
