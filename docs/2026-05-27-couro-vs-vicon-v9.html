Couro vs Vicon — phased features unlock

v9 · 2026-05-27 · phased temporal sampling lifted 5 metric × view slots to new accuracy ceiling

21 of 25 deploy-ready slots now (up from 20). And the strongest deploys got dramatically stronger — knee_angle_r front_oblique_right hit r=0.80, top-tier territory for biomechanical CV from a single phone camera.

What changed. Three explorations tested in this round:

  1. v8 — per-subject anthropometric calibration + Savgol smoothing + confidence threshold. Result: net negative. The ridge regression was implicitly correcting for the Winter-2009 population bias; per-subject calibration broke that structure.
  2. v9 — phased temporal sampling (5 angles per metric across the loading window). Result: major win on the weakest slots. Captures the time-dependent dynamics the summary-stat approach was missing.
  3. Investigated production pose model. Couro has one pose backbone at inference (RTMPose-X Halpe-26). MMPose framework is installed, so swapping for a better keypoint model (DWPose, WholeBody-133) is plausible future work.

The 0.80 result. Knee flexion ROM from front-oblique-right camera correlates with Vicon at r=0.80 — that's better than many commercial markerless systems achieve from multi-camera setups.

2. Why phased features helped (and the v8 calibration didn't)

Old summary statistics compressed ~200 frames of motion into ~10 scalars per trial — ROM, peak, at-contact. That's 95% information loss. Phased features sample the angle at 5 evenly-spaced points across the loading window:

loading window: [initial_contact, pushoff] (typically 100–230ms)

phase 0 = angle at initial contact (foot lands)
phase 1 = angle at +25% loading
phase 2 = angle at +50% loading (deepest compression)
phase 3 = angle at +75% loading
phase 4 = angle at pushoff (foot leaves)

This gives the regression access to the shape of the motion curve, not just its extremes. For metrics like knee flexion in oblique views — where the depth of the curve matters more than the ROM — that extra info is exactly what was missing.

Why v8 calibration failed (per-subject anthropometric overrides): the regression was already learning to correct for the systematic Winter-2009 bias because it was the same across subjects. Replacing with subject-specific anthropometrics broke that consistent structure — each subject now had an idiosyncratic bias pattern, harder to learn from 54 trials. Counterintuitive but real: a wrong-but-consistent prior is sometimes better than a noisy-but-personalized one when data is scarce.

8. The realistic remaining levers

  1. Better pose backbone — MMPose framework is already in production. Swapping RTMPose-X for DWPose or WholeBody-133 would give cleaner foot/heel keypoints, which is the bottleneck on the 3 still-failing ankle/adduction slots. ~1 week to plumb through.
  2. Gradient boosting on the same features — Linear ridge can't capture hip-knee-ankle phase couplings. With the new phased feature set (more features per trial), GBM with careful regularization might find more signal. Last algorithmic option I haven't tested. ~3 hours.
  3. Sport-specific data — current numbers are drop-jump only. AthletePose3D commercial license or custom Couro mocap data are the two paths. Required regardless for AUSL/Cal softball + Sharks hockey credibility.
