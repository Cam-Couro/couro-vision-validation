What we just learned

  • 1 Couro is already on the right path — I missed it on the first code scan. The knee_rotation.py file in metrics_calculator uses a 6-feature linear regression to predict 3D knee rotation from 2D-observable features (knee_flex, hip_adduction, valgus, valgus_velocity, hip_rotation_proxy, knee_flex_velocity). It's trained on ACL Jump-Landing 3D ground truth, gets r=0.47, explicitly view-aware ("Valid in FRONTAL or REAR camera views"). This is the right approach for sports — generic 2D→3D pose lifting (MotionBERT etc.) doesn't work on athletic motions because their training data is mostly daily activities.
  • 2 I applied the same pattern to hip flexion ROM and it worked. 7 features (knee/hip flex ROM, trunk lean, pelvis tilt, knee L/R asymmetry, hip vertical displacement, hip flex velocity peak), ridge regression with z-scored features, leave-one-subject-out cross-validation on 9 subjects. Front-view (Cam2) MAE dropped from 46° to 13°, RMSE from 48° to 21°. Side-view (Cam0) RMSE dropped from 22° to 9° — competitive with academic 2-camera baselines.
  • 3 The coefficients are saved as JSON, ready to drop in. Same format as knee_rotation.py's existing model. Drop the JSON in, add a HipFlexionRomCalculator class that follows the existing pattern, route by view bucket. Engineering effort: 1-2 days.
  • 4 This recipe extends to every metric × view combination. The OpenCap data we just processed is exactly the calibration set Couro needs. Same approach for hip adduction, trunk lean, ankle dorsiflexion, knee valgus — pick 2D-observable proxies, fit on 9 subjects, validate on 1. Realistic effort to do a complete set across all view buckets and all major metrics: 2-3 weeks. End result: Couro single-phone front/back accuracy approaches multi-camera academic systems.

How the regression actually works

Same recipe as Couro's existing knee_rotation.py:

hip_flex_rom_pred = w1 · hip_flex_rom_2d_estimate
                  + w2 · knee_flex_rom_2d_estimate
                  + w3 · trunk_lean_rom
                  + w4 · pelvis_tilt_rom
                  + w5 · knee_flex_L_R_asymmetry
                  + w6 · hip_vertical_displacement_px
                  + w7 · hip_flex_velocity_peak
                  + intercept

The features are all 2D-observable from a single camera. The coefficients are learned per camera-view bucket (different weights for side vs front vs oblique). Training: ridge regression with z-score normalization, alpha=10. 30 seconds of compute per camera bucket on a laptop.

Honest caveats

Pearson r is low on front-view (0.23). The regression captures the population mean and bias-corrects well (MAE 13°), but doesn't track individual variation strongly. For population-level scoring this is fine. For individual coaching feedback ("is THIS athlete bending less today than yesterday?"), the side-view source remains the gold standard.

Trained on drop jumps only (270 trials). The OpenCap LabValidation dataset is drop jumps + squats + walking + sit-to-stand. We trained on the DJ subset. For other movement contexts (sprint, basketball cuts, soccer kicks), the regression coefficients need to be retrained on movement-specific data. The recipe is the same; the coefficients differ.

9-subject training set is small. Adding more subjects (Couro's customer footage paired with mocap, or further OpenCap-equivalent collections) will tighten the regression — particularly the random-scatter component (currently SD ≈ 9° on side, ≈ 21° on front-center).

This is one metric (hip flex ROM). Saad still has to do the same exercise for hip adduction, ankle dorsiflexion, trunk lean, knee valgus, etc. The approach is proven — but extending to a full per-(metric × view) coverage matrix is 2-3 weeks of engineering, not 30 minutes.

This is the path that "fixes front and back accuracy" for Couro. Not 2D→3D pose lifting (doesn't work on sports). Not multi-camera capture (defeats the one-phone pitch). Per-metric biomechanical regression, trained on movement-specific 3D mocap ground truth, view-aware in the scoring config — exactly what the knee_rotation regression already does, scaled to every metric × view combination that matters.
